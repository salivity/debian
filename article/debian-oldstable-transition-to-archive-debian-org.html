Debian Oldstable Transition to archive.debian.org

When a Debian release reaches the end of its life cycle and official support terminates, it is permanently retired from primary mirror networks and moved to archive.debian.org. This article outlines the transition process that occurs once a Debian release moves beyond oldstable and security support concludes, detailing mirror decommissioning, repository freezing, and the steps required to access archived packages.

The Debian Lifecycle Stages

A Debian release progresses through several stages: testing, stable, oldstable, and occasionally oldoldstable. While designated as stable and oldstable, the release receives active maintenance, including regular security patches from the Debian Security Team.

When a newer distribution is released, the current oldstable release typically transitions to Long Term Support (LTS), handled by a dedicated team rather than the main security team. Once LTS (and any potential Extended LTS) reaches its final expiration date, the operating system reaches End of Life (EOL) status.

Removal from Main Mirrors

Active Debian releases are distributed globally across primary content delivery networks and mirrors via deb.debian.org. Mirror operators have finite storage capacity; maintaining discontinued distributions alongside current releases is unsustainable.

Once a release is declared EOL:

  1. The Debian FTP Masters initiate the deprecation process.
  2. The release suite (e.g., stretch, jessie, buster) is removed from the primary Debian package pool on active mirrors.
  3. Upstream sync scripts stop mirroring the deprecated distribution directories, effectively causing standard apt update commands pointing to standard mirrors to return 404 Not Found errors.

Transfer and Freezing on archive.debian.org

Simultaneously with its removal from main mirrors, the entire distribution tree is preserved on archive.debian.org. This dedicated host acts as a historical repository for all discontinued Debian releases and unmaintained architectures.

During this transition:

  • Package Pools are Preserved: All binary packages (.deb), source packages, and release metadata files (InRelease, Release, Release.gpg) are migrated or repointed within the archive's filesystem.
  • State is Frozen: The archive represents a final snapshot of the operating system at the moment support ended. No further software updates, security fixes, or bug corrections are ever added to the distribution.
  • Architectures are Consolidated: If certain hardware architectures were dropped earlier in the cycle, the archive keeps the final state of all architectures that were supported during the release's lifetime.

Impact on Package Management

Systems that remain deployed on an archived Debian release will lose the ability to install or update packages using default repository configurations. To continue using the APT package manager on an archived release, the /etc/apt/sources.list configuration must be redirected to archive.debian.org.

Furthermore, because archived releases are no longer updated, the release metadata's Valid-Until timestamp eventually expires. Package management tools require configuration adjustments—such as passing Acquire::Check-Valid-Until "false"; to APT—to allow installation from the static archive without security signature errors.
