How Debian usrmerge Converts Historic Directories

The usrmerge package in Debian transitions systems from the legacy split-filesystem layout to a modernized, unified directory structure by consolidating /bin, /sbin, /lib, and related system directories into /usr. This article explains the technical mechanics behind this conversion, the historical reasons for the split, the safety checks performed during the merge, and how compatibility symlinks ensure uninterrupted system operation.

The Historical Split vs. Unified Paths

In early Unix and Linux environments, storage limitations necessitated splitting binaries and libraries across different physical drives or partitions. Vital maintenance and recovery tools were placed on the root filesystem in /bin, /sbin, and /lib to allow booting and repairs before the secondary /usr partition could be mounted.

Modern hardware and initramfs systems made this distinction obsolete. Maintaining duplicate directory hierarchies added unnecessary complexity to package management, software search paths ($PATH), and system maintenance. A unified /usr directory tree simplifies the operating system layout, allowing the entire base OS to be mounted read-only, snapshotted, or shared across containers.

Target Directories for Conversion

The usrmerge package converts four primary top-level directories into symbolic links pointing to their counterparts inside /usr:

  • /bin becomes a symlink to usr/bin
  • /sbin becomes a symlink to usr/sbin
  • /lib becomes a symlink to usr/lib
  • Architecture-specific libraries (such as /lib32, /lib64, and /libo32) become symlinks to their corresponding /usr/lib* paths.

Pre-Conversion Safety and Sanity Checks

Before altering any files, the core conversion script (convert-usrmerge, written in Perl) executes a sequence of non-destructive integrity checks to prevent system breakage:

  1. Conflict Detection: The script scans both locations (for example, /bin/grep and /usr/bin/grep). If a file exists in both places, it inspects whether they are identical hard links, matching symlinks, or identical content. If two differing files share the same relative path, the script halts with an error to prevent data loss.
  2. Symlink and Alias Validation: It verifies that directories are not already configured incorrectly, partially converted, or blocked by non-standard mounts.
  3. Storage and Filesystem Checks: It ensures the destination filesystem inside /usr has sufficient free space, supported inode capacities, and does not reside on a separate read-only mount during migration.

If any check fails, the conversion terminates immediately, leaving the existing filesystem untouched.

The Conversion Process

Once the environment passes all validation checks, usrmerge systematically migrates files and directories:

  1. Directory Tree Duplication: For any nested directory within a root path (such as subfolders within /lib), identical directory paths are created within /usr.
  2. File Relocation: Files residing exclusively in root directories are moved to their respective /usr destinations. Because hard links cannot cross filesystem boundaries, files are copied and unlinked if separate partitions were historically used, though standard Debian configurations perform this directly within the same underlying filesystem.
  3. Replacing Root Directories with Symlinks: Once an original root directory is emptied, it is deleted. The script immediately creates a relative symbolic link in its place pointing to the consolidated /usr path (e.g., ln -s usr/bin /bin).
  4. Dynamic Linker Handling: The dynamic linker (such as /lib64/ld-linux-x86-64.so.2) is handled carefully so executing processes, including the Perl interpreter running the migration script, do not lose access to shared runtime libraries mid-execution.

Post-Migration Compatibility

After the merge completes, existing software, hardcoded scripts, and shell configurations function without modification. A call to /bin/sh or /usr/bin/sh accesses the exact same binary because /bin directly resolves to usr/bin. Debian packages can then safely install files directly into /usr, completing the operating system's transition to a unified filesystem hierarchy.
