How to Automate Debian BTS Tagging with tagpending

The tagpending utility automates the process of marking reported bugs as "pending" in the Debian Bug Tracking System (BTS) by parsing a package's changelog file. Instead of requiring maintainers to manually compose and send control emails to the BTS, tagpending detects which bugs are addressed by upcoming package releases and automatically submits the required status changes. This ensures that issue trackers remain synchronized with source repositories with minimal manual overhead.

Changelog Parsing

The automation process begins locally when a developer runs tagpending from within the root directory of a Debian source package. The tool, which is part of the standard devscripts package suite, inspects the debian/changelog file. It scans the latest unreleased entry for Debian's standardized closure syntax—specifically lines containing directives such as Closes: #123456.

BTS Status Querying

Once tagpending extracts the identified bug numbers, it queries the Debian BTS server (using SOAP or Debbugs interfaces) to verify the current metadata of each bug. The tool cross-references the list against two primary criteria:

  1. Whether the bug is already marked as closed.
  2. Whether the pending tag is already present on the bug report.

Bugs that are already closed or already carry the pending tag are filtered out of the operational queue, preventing duplicate notifications and unnecessary status modifications.

Dispatching Control Commands

For all relevant, unhandled bugs, tagpending generates the control instructions required by the Debian BTS. The Debian BTS processes administrative actions via email commands sent to control@bugs.debian.org.

tagpending automates this communication pipeline by:

  • Formulating the appropriate BTS control command (tag <bug_number> + pending).
  • Optionally incorporating changelog excerpts as explanatory comments to provide context on how the issue was resolved.
  • Transmitting the formatted command message via the local Mail Transport Agent (MTA) or a configured SMTP server directly to the Debian BTS mail interface.

Interactive and Automated Integration

By default, tagpending prompts the maintainer to review and confirm the proposed changes before transmission, allowing for manual verification. However, maintainers can run it with flags such as --silent or inside automated scripts, Version Control System (VCS) commit hooks, and Continuous Integration (CI) pipelines. When integrated into package build pipelines, tagpending completely removes the need for manual status tracking, ensuring users and other maintainers are immediately aware that a fix is committed and waiting for the next package upload.
