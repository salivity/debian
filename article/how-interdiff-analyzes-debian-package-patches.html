How Interdiff Analyzes Debian Package Patches

The interdiff utility, part of the patchutils package, analyzes differences between two unified diff files directly without requiring access to the underlying source tree. In Debian package maintenance, it serves as a critical auditing tool for comparing package revisions, allowing maintainers and security teams to isolate the exact modifications introduced between successive Debian revision releases (such as between -1 and -2, or during Non-Maintainer Uploads).

Unified Diff Parsing

interdiff operates directly on unified diff format files (diff -u). Instead of executing a diff against concrete files on a filesystem, it parses the hunk headers (@@ -start,len +start,len @@), context lines, additions (+), and deletions (-) contained within each patch.

When analyzing two revisions of a Debian package patch, interdiff reads:

  1. Patch A: The baseline patch (e.g., the Debian changes from revision 1.0-1).
  2. Patch B: The updated patch (e.g., the Debian changes from revision 1.0-2).

Algorithmic Reconciliation of Hunks

To generate an accurate diff of diffs, interdiff constructs a virtual representation of the changes:

  • Offset and Line Drift Calculation: Successive modifications to a package often shift line numbers. interdiff tracks line offsets generated by additions or deletions in Patch A so it can align matching contexts in Patch B, even if the line numbers in the hunk headers differ.
  • Context Normalization: It evaluates the leading and trailing context lines surrounding each change. If Patch B modifies code in the same function or file region as Patch A, interdiff aligns these hunks by their shared context rather than strict file offsets.
  • Delta Computation: Once hunks are aligned, the tool calculates the net change. Additions present in Patch A but removed in Patch B appear as deletions (-). Additions introduced only in Patch B appear as additions (+). Overlapping modifications are combined to show only the differential change.

Role in Debian Package Maintenance

Debian package maintenance relies heavily on patch management systems, notably quilt, which stores patches in debian/patches/. When packages undergo updates, maintainers use interdiff to:

  • Inspect NMUs and Team Uploads: Reviewers can isolate the changes made by another contributor without re-evaluating the entire upstream source or previously accepted Debian patches.
  • Track Upstream Rebases: When rebasing a Debian patch series onto a new upstream release, interdiff confirms that custom packaging patches were refreshed correctly without accidentally dropping Debian-specific fixes.
  • Power Higher-Level Tools: Debian’s debdiff tool frequently invokes interdiff under the hood when comparing .diff.gz or .debian.tar.xz metadata between two source package control files (.dsc).

By processing diff syntax mathematically rather than reading full source trees, interdiff ensures fast, deterministic verification of patch evolution across Debian package versions.
